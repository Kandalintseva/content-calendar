# Как запустить календарь публикаций

Настройка выполняется один раз. После неё вы открываете обычную ссылку на MacBook или iPhone и работаете только с календарём.

## Что понадобится

1. Бесплатный проект [Supabase](https://supabase.com/dashboard/projects).
2. Репозиторий [GitHub](https://github.com/new) с файлами этого проекта.
3. Telegram-бот, созданный в [@BotFather](https://t.me/BotFather) командой `/newbot`.

## 1. Подключите Supabase

В терминале в папке проекта выполните:

```bash
npm install
npx supabase login
npx supabase link --project-ref ВАШ_PROJECT_REF
npx supabase db push
npx supabase functions deploy
```

`Project ref` виден в адресе проекта: `https://supabase.com/dashboard/project/PROJECT_REF`.

## 2. Подключите Telegram

Скопируйте токен из BotFather. Скрипт сам создаст защищённые случайные секреты. Выполните:

```bash
chmod +x scripts/configure-telegram.sh
./scripts/configure-telegram.sh 'ТОКЕН_ОТ_BOTFATHER' 'PROJECT_REF'
```

Скрипт сам сохранит токен в серверных секретах Supabase, настроит webhook и запишет `CRON_SECRET` в защищённый локальный файл `.setup-secrets`. Этот файл исключён из Git. Токен бота не попадает в сайт или репозиторий.

## 3. Включите серверное расписание

Откройте [SQL Editor](https://supabase.com/dashboard/project/_/sql/new), вставьте содержимое `supabase/setup-cron.sql`, замените:

- `YOUR_PROJECT_REF` на Project ref;
- `PASTE_A_LONG_RANDOM_CRON_SECRET` на значение из файла `.setup-secrets`.

Нажмите **Run**. Supabase будет проверять напоминания каждые 5 минут независимо от браузера.

## 4. Опубликуйте сайт на GitHub Pages

В GitHub откройте **Settings → Secrets and variables → Actions → Variables** и добавьте:

- `VITE_SUPABASE_URL` — `https://PROJECT_REF.supabase.co`;
- `VITE_SUPABASE_ANON_KEY` — публичный ключ из Supabase **Settings → API Keys**;
- `VITE_TELEGRAM_BOT_USERNAME` — имя бота без `@`.

В **Settings → Pages → Build and deployment** выберите **GitHub Actions**. Запустите workflow **Deploy app to GitHub Pages** или отправьте изменения в ветку `main`. Готовая ссылка появится в том же разделе Pages.

В Supabase откройте **Authentication → URL Configuration**:

- укажите ссылку GitHub Pages как **Site URL**;
- добавьте её же в **Redirect URLs**.

## 5. Добавьте бесплатный резерв расписания

В GitHub **Settings → Secrets and variables → Actions → Secrets** добавьте:

- `NOTIFICATION_FUNCTION_URL` — `https://PROJECT_REF.supabase.co/functions/v1/notifications-dispatch`;
- `CRON_SECRET` — значение из файла `.setup-secrets`.

Workflow `Notification scheduler fallback` запускается каждые 5 минут. Он безопасно работает параллельно с Supabase Cron: база не позволит отправить одно уведомление дважды. У публичных репозиториев GitHub может отключить расписание после 60 дней без активности, поэтому Supabase Cron остаётся основным способом.

## Первый вход

1. Откройте готовую ссылку и нажмите **Создать доступ**.
2. Введите email и пароль. Если Supabase попросит подтвердить email — откройте письмо.
3. После первого пользователя рекомендуется выключить новые регистрации: Supabase **Authentication → Providers → Email → Allow new users to sign up**.
4. Откройте настройки `⚙`, нажмите **Подключить Telegram**, затем **Start** в Telegram.
5. Вернитесь в настройки: статус станет зелёным. Нажмите **Отправить тест**.

## Ежедневная работа

- Нажмите на день → введите название → **Добавить**.
- Нажмите на карточку, чтобы изменить публикацию. Изменения сохраняются автоматически.
- Включите **Уже опубликовано**, чтобы остановить напоминания.
- Для удаления откройте карточку и нажмите **Удалить**.

## Если уведомление не пришло

1. В приложении нажмите **Отправить тест**.
2. В Supabase откройте **Edge Functions → Logs** и выберите `notifications-dispatch`.
3. В **Integrations → Cron** проверьте последний запуск `content-calendar-notifications`.
4. Убедитесь, что бот не заблокирован в Telegram.
5. Если тест не проходит, отключите Telegram в приложении и подключите снова.

## Резервное копирование

На бесплатном тарифе Supabase автоматические резервные копии могут быть недоступны. Раз в месяц экспортируйте таблицу `posts` в CSV из **Table Editor**. Для критичных данных используйте платный тариф с автоматическими резервными копиями.
